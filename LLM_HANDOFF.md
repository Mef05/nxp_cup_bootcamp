# NXP Cup - Autonomous Line Following Car
**AI Context & Handoff Document**

This document contains critical information about the hardware quirks, mathematical models, and algorithms used in this NXP Cup codebase. **Any LLM assisting with this project MUST read this file before making modifications to the motor logic, steering, or line detection.**

## 1. Hardware Setup & Pinout
* **Board:** NXP FRDM-MCXN947
* **Camera:** Pixy2 Line Tracking algorithm (connected via I2C `LPI2C2`, address `0x54U`).
* **Steering Servo:** Driven by `CTIMER2_MAT2` (PORT1_12). 
  * Values range from `-100` (Max Left) to `+100` (Max Right).
* **Drive Motors:** 2x DC Motors on an H-Bridge.
  * **PWM Pins:** `CTIMER0_MAT1` (PORT0_25) for Left, `CTIMER0_MAT2` (PORT0_26) for Right.
  * **DIR Pins:** `GPIO0_24` (Left), `GPIO0_27` (Right).
  * **Wiring Note:** The user manually matched the physical motor polarities. Setting `SPEED_LEFT` and `SPEED_RIGHT` to positive values (e.g., 35) drives BOTH motors FORWARD.

## 2. CRITICAL BUG RESOLVED: NXP SDK PWM Inversion
The most complex bug solved in this codebase was related to the motor speeds. 
The NXP SDK function `CTIMER_UpdatePwmDutycycle()` (in `fsl_ctimer.c`) calculates the duty cycle backwards:
```c
// NXP SDK Implementation
pulsePeriod = ((uint64_t)period * (100U - (uint32_t)dutyCyclePercent)) / 100U;
```
**The Fix (in `source/hbridge.c`):**
Due to the H-Bridge wiring and NXP SDK logic, the duty cycle calculation is asymmetric based on the `DIR` pin:
* **Forward (`DIR=1`)**: Motor receives power when PWM is LOW. SDK sets LOW time = `100 - duty`. Thus, we pass `duty = 100 - speed`.
* **Reverse (`DIR=0`)**: Motor receives power when PWM is HIGH. SDK sets HIGH time = `duty`. Thus, we pass `duty = speed`.
* The `HbridgeSpeed()` function abstracts this inversion completely. 
* `HbridgeSpeed(12, 12)` guarantees exactly 12% power applied forward to both motors.

## 3. The Control Loop (`source/main.c`)
The main loop runs as fast as the I2C Pixy2 polling allows.

### Line Tracking Algorithm (Dual-Margin)
1. **Vector Filtering:** The camera returns up to 10 vectors. Vectors that are too horizontal (`dy < MIN_DY`) are discarded as noise/crosswalks.
2. **Lane Separation:** Vectors are sorted into "Left Lane" (`x < IMAGE_CENTER_X`) and "Right Lane" (`x > IMAGE_CENTER_X`).
3. **Center Calculation:** The algorithm calculates `center_bot` (closest to car) and `center_top` (furthest from car) by averaging the left and right lane vectors. 
4. **Error Metrics:** 
   * `cte` (Cross-Track Error) = `center_bot - IMAGE_CENTER_X`
   * `heading` (Angle) = `center_top - center_bot`
   * `error = (WEIGHT_CTE * cte) + (WEIGHT_HEADING * heading)`

### Steering (PD Controller)
* Calculates `steer_cmd = (KP * error) + (KD * error_derivative)`.
* Uses `STEER_ALPHA` for exponential smoothing (currently `0.0f` for raw, aggressive response).

### Drivetrain (Electronic Differential & Failsafes)
* **Startup Jolt Prevention:** `HbridgeBrake()` is called *before* `pixy_init()`. Pixy initialization takes ~300ms over I2C. If motors are not explicitly braked, the car will jolt randomly on hardware reset.
* **Failsafe:** If the line is lost (`frames_lost > 0`), the car halves its speed. If lost for >= 10 frames, it triggers a full `HbridgeBrake()`.
* **Electronic Differential:** When cornering, the outer wheel spins at normal speed, but the inner wheel's speed is reduced proportionally to the steering angle (`diff_factor = current_steer * 0.005f`). This prevents slippage and tightens the turn radius.

## 4. Tuning Parameters (Quick Reference)
All live parameters are located in `main()`, except base speeds which are in `include/Config.h`.
* `KP`, `KD`: Standard PD tuning.
* `WEIGHT_HEADING`: Keep this relatively low (e.g., 0.4) because the "top" of the vectors from Pixy2 tends to jitter wildly at long distances.
* `IMAGE_CENTER_X = 39.0f`: The calibrated physical center of the Pixy2 frame.
* `SPEED_LEFT` / `SPEED_RIGHT` (in `Config.h`): Safe testing speed is ~35. Max competitive speed is ~60-80.

## 5. Next Steps / Future Work
* If the car oscillates too much on straights: Decrease `KP` or increase `KD`.
* If the car cuts corners too aggressively: Decrease `diff_factor` multiplier or `WEIGHT_HEADING`.
* If track lighting changes: Pixy2 might need retraining/re-tuning via PixyMon.
